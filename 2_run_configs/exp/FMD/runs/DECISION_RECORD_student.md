## 2. Student architecture (one model per arm, FM-free at inference)
Unet1D (E0 / LUO arch, unchanged), with `unet.encoder` replaced by `student_model.StudentEncoder`:
- **Input**: the 224-px render of the unit (fmd_harness render.py: 64-px eval-canvas ink × 3.5, thickness 7, anti-aliased), inverted to white ink on black in [0, 1], 1 channel. This is the same polarity and scaling convention as the 64-px condition.
- **Encoder**: ViT-S/14. Patch-embed Conv2d(1, 384, 14, stride 14) gives a 16×16 token grid. A fixed 2-D sin-cos position embedding is used, with no CLS or register tokens. There are 12 pre-norm blocks (MHSA with 6 heads, MLP 4×, GELU), followed by a final LayerNorm. The output is tokens (b, 256, 384), row-major. "FM-sized" means the FM token interface: 224-px input, 14-px patches (one patch = one 4×4-px cell of the 64 canvas), and a 16×16 grid, the G16 grid of the screen. Width 384 / depth 12 is the smallest member of the DINOv2 ViT family with this interface. Init: truncated-normal std 0.02 for Linear, xavier-uniform for the patch projection, LayerNorm = (1, 0). Init uses a private generator seeded 20261104, so the init is identical in every arm and does not touch the global RNG stream. **No FM weights initialise the student.**
- **Level heads** keep every pretrained cross-attention's input width and the PE position ↔ canvas-location map of the old encoder. Each map's channel width and size equal the old map's:
| map | old (64-px CNN) | student derivation | head params |
|---|---|---|---|
| 0 | 64 ch @64×64 | LayerNorm → Linear(384, 64·16) → pixel-shuffle ×4 (token (r, c) → 64-canvas pixels (4r+i, 4c+j)) | 395,008 |
| 1 | 64 ch @32×32 | LayerNorm → Linear(384, 64·4) → pixel-shuffle ×2 | 99,328 |
| 2 | 128 ch @16×16 | LayerNorm → Linear(384, 128) (one token per 4×4-px cell) | 50,048 |
| 3 | 256 ch @8×8 | LayerNorm → 2×2 space-to-depth (1,536) → Linear(1536, 256) (same pattern as the old encoder's downsample) | 394,240 |
| 4 | 512 ch @4×4 | LayerNorm → 4×4 space-to-depth (6,144) → Linear(6144, 512) | 3,147,008 |
- **Parameter counts** (measured, smoke run_config): old ImageEncoder 3,955,264; new encoder 25,455,616 (ViT 21,369,984 + heads 4,085,632); student Unet1D total 48,592,388 vs the old 27,092,036.
- **Initialisation of the rest**: the nominee's RTL route is merged into one plain Unet1D state dict: LUO ms6 EMA + tier S (zero) + tier U from `ema_trainable` of checkpoint_000004, via `HSRUnet1D.merged_state_dict(('S','U'))`. All non-encoder keys (409 keys) load into the student. The old encoder's 78 keys, including its merged encoder-group LoRA, are dropped. Merge check: the merged plain Unet1D and the routed HSR (RTL route) were compared on a fixed random input with the old 64-px encoder; max |Δ| = 2.15e-6 (VPS smoke 360, 4090).
- **Trainable vs frozen**: the merged U-Net weights (23,136,772 params) are frozen. Trainable are (a) the whole new encoder (25,455,616) and (b) ONE fresh LoRA tier at the nominee's adapter targets and ranks minus the old encoder group: cross / attn / linear at r32/α32, temporal / tconv / tmlp at r16/α16, 124 wrapped modules, 2,515,008 params (= the nominee's 2,611,264 per tier − 96,256 encoder-group params). A init uses the nominee's seeds and B = 0, so at step 0 the U-Net equals the merged nominee. Total trainable 27,970,624, identical in A, B and C'. Reason: the nominee adapted the U-Net only through a LoRA tier on frozen weights; the student keeps the same U-Net adaptation capacity, and the new encoder must be trained because it has no pretrained weights.
- **S/U tiers and router**: S is zero and U is merged, so there is no routing inside the student checkpoint. The ScriptCNN router stays the nominee's test-time convention (Section 5).

## 4. Guidance losses (prereg Section 6, A1)
- Alignment point: the student's final-LayerNorm encoder tokens (b, 256, 384), before the level heads.
- Projector: Linear(384, 2048) → SiLU → Linear(2048, 2048) → SiLU → Linear(2048, D_fm), default PyTorch init under a forked RNG seeded 20261105, so the global RNG stream, and therefore every shared init, batch and noise draw, is identical across A, B and C'. Params: 7,083,008 for D = 1024 (B) and 7,607,552 for D = 1280 (C'). Optimised with the same Adam and lr; not in the EMA; **discarded at save**. The inference checkpoint holds only the plain student Unet1D state dict (577 keys, 48,592,388 float params). The save step asserts that its key set equals a fresh plain student's key set, holds no projector/opt/EMA/trainable entries, and reloads into a plain student; max |Δ| vs the wrapped EMA model is recorded.
- Loss per micro-batch: L = L_den + λ·L_REPA, λ = 0.5. L_den is the nominee's (Nagamatsu pred_noise MSE × loss_weight[t], mean). L_REPA = mean over batch and 256 tokens of −cos(projector(token), FM token).

Outputs follow the lane_score.py PREDS format: `<RUN>/preds/val1000_ouhdl__<label>_ms4_thr0p5_<lane>__seed<s>_preds.npz` + `.json` sidecar (set, route_mode, seed, npz_clusterA = `data/ouhdl_e0_v3/e0_val.npz`, source_sha256_expected 25451031..., preds_sha256, checkpoint sha256, family counts).

## 6. Deviations from the nominee (each justified)
1. The image encoder and its input (the object of this phase), and one fresh LoRA tier instead of tiers S + U with the encoder group (the old encoder no longer exists).
2. No in-job gate at step 2,000 and no in-training validation loss. The prereg budget fixes the read at step 4,000 (ms4) for every arm. The nominee gate's UNIPEN-de clause tests the LTR backbone path, which the student does not change.
3. Sampling noise order: torch.manual_seed(seed) once. RTL units are sampled first in val1000 order, then below-threshold units. The nominee mixed both routes in each batch, so per-unit initial noise differs from the nominee's reads. It is identical across A, B and C', because the router is arm-independent.
4. The mirror_x frame on the 224-px image uses the same shifted-flip rule at W = 224 (Section 3 checks).
5. Interpretation of "precomputed on the training renders": REPA targets are FM tokens of the framed 224-px render, the image the student encodes.
6. DINOv3 targets were extracted on CPU; the screen features were extracted on a GPU. Reproduction difference: max |Δ| 9.8e-4.
7. Below-threshold val1000 units are sampled by the LUO backbone (nominee convention). Their predictions are identical across arms; their count is in every sidecar (`family_counts`).
