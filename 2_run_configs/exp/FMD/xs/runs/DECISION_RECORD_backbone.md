## 3. Regimes and recipe (A4.2, A6)
- WARM: online AND EMA U-Net <- LUO ms6 EMA weights for every non-encoder module (`exp/M5/runs/luo/checkpoints/checkpoint_000006.pt`, sha256 ab6b178d...812c); new encoder; fresh Adam; 40,000 steps; milestones every 10,000 (ms1-ms4).
- SCRATCH: `torch.manual_seed(20261016)` then Unet1D(E0_ARCH) (m5_train.py order), encoder replaced; 100,000 steps; milestones ms1-ms10.
- Optimiser: Adam betas (0.9, 0.99); group 1 = U-Net (all non-encoder parameters) lr 8e-5, no warm-up; group 2 = new encoder + level heads + REPA projector, lr 2e-4, linear warm-up 200 steps (A4.2). Grad-clip 1.0 on the diffusion parameters (LUO); the projector is clipped separately at 1.0. fp16 autocast + GradScaler. EMA = ema_pytorch EMA(beta 0.995, update_every 10) on rank 0 (Trainer1D). Loss = the repo's GaussianDiffusion1D p_losses (pred_noise, cosine, 1,000 steps) unchanged.
- Data: `data/m5_multiscript_v1/m5_luo_train.npz` (sha256 690441b6...), Trainer1D split (train_fraction 0.99, random_split seed 0) -> the same 79,200 training units as LUO ms6; the 800 held-out units give a validation loss every 1,000 steps. Seed 20261016; after a requeue seed = 20261016 + step (E0 change 3).
- Batch (A6, 512 sequences per optimiser step), layout rule fixed here: 2 GPUs >= 40 GB -> 64 per process x accum 4; 1 GPU >= 40 GB -> 128 x accum 4; any GPU < 40 GB (A4000 16 GB, A30 24 GB, RTX 4090 24 GB) -> 32 per process x accum 16 / n_GPU. Losses are means over the micro-batch, so the accumulated gradient equals the 512-unit mean in every layout (no batch-statistics layers). The layout of every job is written to its `job_history.txt`.
- Encoder input: the 224-px render (fmd_harness 1.0.1 `render.render224` = uhwr_eval.render_image, 64-px eval canvas x 3.5, thickness 7, anti-aliased, black ink on white; the trainer inverts to white-on-black [0,1]), identity frame, no thickness augmentation (differs from LUO's 64-px thickness 1-3 augmentation; recorded with every result).

## 7. Gate, priority, races (A4.3)
- In-job check: `verdict_<fm>.json` of the lane mirror at start (and after every requeue) and at every 10,000-step save; status FAIL -> file `GATE_FAIL` ({fm, step, verdict sha256, utc}), checkpoints kept, exit 0; PENDING / PASS_XS / PASS_URDU_ONLY / missing -> continue. Smoke-tested at start and mid-run.
- Controller `controller/gate_controller.py` (A4.3 'fmdx_controller'): cancels FAIL FMs' arms (all of the cluster's fx_<arm> jobs + queued VPS cmds), never controls (A4.3 a); orders arms warm before scratch, controls first, FM arms by verdict `priority_score` descending (A3.6), ties fm id; applies nice values and a GPU cap by scontrol hold/release, releasing only arms whose inputs exist; resolves races from the VPS race locks; logs to `admin/controller_log.md`, `cancellation_log.md`, `arm_log.md` and `exp/CAND/queue/cand_log.md`; updates `admin/arm_queue.csv`.
- Race rule: every copy takes an atomic lock `stage/exp/FMD/xs/race/<arm>` on the VPS hub when it STARTS (CLUSTER-A/CLUSTER-B: mkdir over ssh; VPS: local mkdir); the first copy wins; a later copy writes RACE_LOST.json and exits 0; the controller cancels pending loser copies. Licence lanes: DINOv3-family arms CLUSTER-A + VPS only (A3.3).
- Milestone selection (A4.3 d): LUO rule on the four val250 sets (casia_zh, casia_en, hpl_tamil, iam; 1,000 units), `bb_sample.py` DDIM-50 eta 0 seed 0 EMA on the training lane, `e0_score.py e0` native, `m5_select.py` (lowest mean LDTW, ties higher AIoU).
